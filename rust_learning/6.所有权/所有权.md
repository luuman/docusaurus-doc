### 所有权

目前我们学到的内存回收机制有以下几种

* GC 在程序运行时不断寻找不再使用的内存，典型代表：Java、Go， 这种方式通过定期标记（mark）找出不再被引用的对象，然后将其清理（sweep）掉
* 手动管理，通过函数调用的方式来申请和释放内存，典型代表：C++, OC-MRC
* 自动内存管理，C++的智能指针，OC、Swift的ARC，自动释放池。引入额外代码逻辑释放对象，释放及时但是性能不如gc
* 所有权， rust， 编译器在编译时会根据一系列规则进行检查

Rust 选择了第四种，最妙的是，这种检查只发生在编译期，因此对于程序运行期，不会有任何性能上的损失。

### 所有权原则

> 1. Rust 中每一个值都被一个变量所拥有，该变量被称为值的所有者
> 2. 一个值同时只能被一个变量所拥有，或者说一个值只能拥有一个所有者
> 3. 当所有者(变量)离开作用域范围时，这个值将被丢弃(drop)

__这个规则非常类似c++的唯一性指针，所有权通过move在各个变量之间游走，只不过在c++中是由开发人员显式调用的，而在rust中是编译期间的约束规则，只要我们打破上述规则，编译器就会抛出错误__

### 堆和栈

栈：由高地址到低地址，系统负责分配和释放，栈由于是系统分配，不需要我们通过所有权管理，在栈上的数据交互一般都是值拷贝

堆：系统或程序负责申请，使用完负责释放。由低地址到高地址分配

其他：我们的代码加载时根据代码模块的不同，代码放入代码区，字面量和常量放入常量数据区，静态变量放入全局区。这几个部分是程序加载时已经确定的，我们无法手动分配内存，也无需释放这里的内存，他们的生命周期和进程一致。

我们可以看到需要我们手动管理内存的只有堆区对象，所有权转移也只发生在这里。栈由上自下分配，进入函数自动分配函数包含的变量内存，离开函数释放内存。堆由下自上分配，创建对象分配内存，释放对象释放内存。在进程中如果堆栈分配达到阈值(堆栈指针相遇，堆栈碰头)就会发生内存溢出的崩溃。出现这种场景，如果因为栈，一般是函数递归分配大对象(数组)导致，堆区一般是因为内存泄漏导致。 rust通过所有权机制来保证对象的及时释放。

我们知道rust的所有权转移是通过move语义实现的，但是却不需要我们显示调用，rust提供了编译期检查的机制来向开发者抛出错误。我们要想探索一门语言，探索其编译的中间代码是一种可行的途径。在swift中我们探索过IR代码

### 从类型和内存布局探索所有权

__所有权是指变量和值的交互，我们分类型来探讨：__

##### 基础值类型(整形 浮点 布尔 字符)

```
let a = 10;
let b = a;
```

我们通过前面的章节和代码，了解了这些类型可以在栈区直接存储，而且赋值语句在他们之间是以值传递的形式进行的，这在计算机术语中称作深拷贝，拷贝发生后原对象和目的对象是两个独立副本。

从这个角度来看，因为发生了深拷贝，每个值仍然被一个单独变量持有，不违背编译器的所有权原则

__基础值类型变量关联的内存直接存储值，发生赋值时只是指发生了深拷贝，这不违背前两条规则，当变量的作用域结束被释放时值被丢弃__



##### 字符串

1. String类型

   ```
   let s1 = String::from("hello");
   let s2 = s1;
   ```

   `"hello"`在数据区占用5字节，`String::from("hello")`其分配在堆区占用5或更多字节，长度5字节，s1和s2是一个宽指针，分别占用24字节。

   变量s1有些特殊，并不像上面的变量a一样内存直接存储关联的值。它属于一种间接关联，首个8字节指向堆区，在这个堆内存也是由我们负责的(类似c中的free)。而在rust中我们不需要显示调用释放代码，而是通过所有权来维护释放。

   发生s2指向s1时，s2也在栈区，将s1的栈区值copy，此时s1和s2存储的值完全一致。那么我们就有两个指向堆区的指针，如果不发生所有权转移，堆内存会被__double free__. rust通过move语义将s1的所有权转移给s2，并且如果继续使用s1将会报错。

2. 字符串字面量 &str

   ```
   let s = "hello";
   let s1 = s;
   ```

   `"hello"`在数据区占用5字节, 由于常量区(数据区)的特殊性，它是只读的，而且这部分内存固定大小，声明周期和进程一致。s是宽指针，占用16字节，8字节指针指向常量区，8字节长度。

   当s1指向s，只是copy了16字节，并不会发生所有权的转移。__实际上引用和借用类型都不会发生所有权转移，这个我们在后面探讨__

3. 字符串String引用 &alloc::string::String

   ```
   let s = String::from("hello");
   let s1 = &s;
   ```

   s的内存布局我们就不探索了，它占有8字节，拥有堆区字符串的所有权。s1是指向s的指针(这个和c语言类似)，这个在之前的文章中我们探索过。s1分配在栈上，他的值是个指针也指向一个栈地址，因此他不需要为堆区某个对象负责。__实际上引用和借用类型都不会发生所有权转移，这个我们在后面探讨__

   __&str占用16字节，他可以隐式接收一个&alloc::string::String， 如下：__

   ```
   let mut s = "哈哈哈";
   let s1 = String::from("hello");
   s = &s1;
   ```

   这里s是16字节，&s1占用8字节指向s1，赋值后我们看到s直接指向了堆区的hello，这个结果和我们之前学的字符串切片一致(这里的切片是全部)。__我们一般可以使用&str作为函数参数，在传参时其实传入的是字符串切片__

4. 字符串切片

   切片其实就是对原语义的引用借用，不发生所有权的转移

   

##### 元组

1. 元组中都是基础类型

   ```
   let a: (i32, i32, u8) = (5, 10, 2); // 4 + 4 + 1 = 9 占用12字节
   let b = a;
   ```

   a分配在栈上，占用12字节，b分配在栈上占用12字节，他们是两个独立的副本，不发生所有权转移

2. 元组中有指向堆的类型

   ```
   let a: (i32, i32, String) = (5, 10, String::from("xxx"));
   let b = a;
   ```

   首先$2参数是会发生所有权转移的，那我们有两种猜想？

   * move语句作用于$2, 那么赋值过后 $1 和 $0仍然可以继续访问
   * move语句作用于整个元组, 那么赋值过后整个都不允许在访问

   通过代码实践很容易发现第二条结论是正确的，我们通过MIR中间代码验证一下

   ```
   fn main() {
       let a = (10, String::from("A"));
       let _b = a;
   }
   
   ====================================>
   
   fn main() -> () {
       let mut _0: ();
       let _1: (i32, std::string::String); // 元组
       let mut _2: std::string::String;
       scope 1 {
           let _3: (i32, std::string::String); // 元组
       }
   
       bb0: {
           _2 = <String as From<&str>>::from(const "A") -> [return: bb1, unwind continue]; // _2是字符串
       }
   
       bb1: {
           _1 = (const 10_i32, move _2); // _2所有权转移到_1内部
           _3 = move _1;  // _1 所有权转移到 _3
           drop(_3) -> [return: bb2, unwind continue]; 
       }
   
       bb2: {
           return;
       }
   }
   ```

__我们看到元组赋值是否发生所有权转移和其内部元素相关，如果赋值引起内部元素所有权转移，元组整体所有权也会发生转移__

##### 枚举

### Clone 和 Copy trait

我们知道Clone和copy是两个便捷宏

__Clone其实是实现了一个Clone的方法，方法签名`fn clone(&self) -> Type`, 我们可以通过这个clone方法生成一个全新的副本。而copy是一个语义，只是告诉编译器对赋值语句采用按位赋值的方式，其必须和Clone同时使用，以此来改变赋值时的所有权语义__

为什么copy不能作用于引用和胖指针类型？

copy的语义比较基础就是按位赋值。对于基础类型，所有值都直接存储在他的关联内存中，这种快速赋值比较容易实现而且是两个全新副本。但是间接类型如果按照copy语义进行赋值就必须产生所有权的转移，这就不符合clone的作用了。
