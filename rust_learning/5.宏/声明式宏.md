### 宏

Rust 提供了强大的宏编程能力，使其具有元编程能力。宏编程的本质就是把一棵语法树转换成另一颗语法树，主要作用是避免写大量结构重复的脚手架代码。简单理解就是具备编译期间替换代码的能力。

Rust的宏分为两大类：声明宏 （declarative macro）和 过程宏（procedural macro）

### 声明式宏

#### 定义

声明宏可以用 `macro_rules!`生成。macro_rules 使用模式匹配（类似match匹配），且可以提供多个匹配模式以及匹配后执行对应的代码块，如

```rust
match target {
    模式1 => 表达式1,
    模式2 => {
        语句1;
        语句2;
        表达式2
    },
    _ => 表达式3
}
```

与 match不同的是，宏里的值是一段 Rust 源代码(字面量)，模式用于跟这段源代码的结构相匹配，一旦匹配某个模式，传入宏的那段源代码将被模式关联的代码所替换，最终实现宏展开。我们先看一个简单的例子：

```
macro_rules! times_five {
    ($e:expr) => { 5 * $e };
}

let num1 = times_five![5];
let num2 = times_five!(5);
let num3 = times_five!{5};
println!("num1: {}, num2: {}, num3: {}", num1, num2, num3);
```

times_five是一个声明式宏，其中定义了一种规则，这个规则接受一个表达式输入，如果规则匹配则原文处的代码将呗展开为 5 * 输入表达式。这里有两个点需要注意：

1. 调用宏时不论 [] {} () 均是可行的，匹配规则对包裹标记符并没有要求，只会匹配内容。更多人习惯更多写为() , 然而系统的vec宏就写为[], 这样读写更直观更能反映其为一个数组容器
2. expr可以简单理解为宏类型，expr就是值或表达式的意思

那么除了expr，我们还能定义那些宏类型

```
block: 一个块（即由大括号括起来的一系列语句和/或表达式）
expr: 一个表达式
ident: 一个标识符（包括关键字）
item: 一个项，如函数、结构体、模块、实现等
lifetime: 一个生命周期（例如 'foo、'static 等）
literal: 一个字面量（例如 "Hello World!"、3.14、'🦀' 等）
meta: 一个元项；用于 #[...] 和 #![...] 属性中的内容
pat: 一个模式
path: 一个路径（例如 foo、::std::mem::replace、transmute::<_, int> 等）
stmt: 一个语句
tt: 一个单独的标记树
ty: 一个类型
vis: 可能为空的可见性限定符（例如 pub、pub(in crate) 等）
```

这些不是我们探索的重点, 用到再找就行。 接下来我们定义一个多参数的匹配规则

```
macro_rules! multiply_add {
    ($a:expr, $b:expr, $c:expr) => { $a * ($b + $c) };
}

let num4 = multiply_add![5, 5, 5];
println!("num4: {}", num4);
```

我们能看到输入的三个表达式被 $a $b $c成功匹配

> 还有一个特殊的元变量称为 `$crate`，用于引用当前的 crate

#### 重复项

某些情况下，我们希望接受一些列参数，这些参数个数未知，因此宏就必须支持重复参数的匹配规则。通用规则如下：

`$ ( ... ) sep rep`

`$` 美元符号，表示`()`中的整体是宏定义

`()` 是要被重复的匹配器，用小括号分组

`sep` 是分隔符标记，常见的示例包括逗号（,）和分号（;）, 如果不加分隔符则用空格匹配，分隔符属于完全匹配

`rep` 是必须的重复操作符目前有如下几种(和正则一致)

1. ?  0次或1次
2. \* 0次或多次
3. \+ 1次或多次

__由于 ? 表示最多出现一次，它不能与分隔符一起使用__

重复项在扩展中使用相同的语法，并且重复的元变量只能在扩展中的重复项内部访问,  并且拓展中不需要 `sep` 分隔符。例如

```
macro_rules! mbe {
    ($($e:expr)?) => {
        {
            println!("ruler match ?");
            let mut vec = Vec::new();
            $(
                vec.push(format!("{}", $e));
            )*
            vec
        }
    };
    ($($e:expr),*) => {
        {
            println!("ruler match *");
            let mut vec = Vec::new();
            $(
                vec.push(format!("{}", $e));
            )*
            vec
        }
    };
}

let vec1 = mbe![5];
let vec2 = mbe![5, 5, 5];
println!("vec1: {:?}, vec2: {:?}", vec1, vec2);
```

上面演示了，重复的$e只能在拓展中以相同的规则重复使用，？不能加分隔符， 使用,分割符的也必须用,分隔调用

我们可以在单个拓展中使用多个重复的原变量，如下

```
macro_rules! compare1_two {
    ($($i:expr)*, $($i2:expr)*) => {
        let mut sum1 = 0;
        let mut sum2 = 0;
        $( 
            sum1 += $i;
            sum2 += $i2; 
        )*
        if sum1 > sum2 {
            println!("{} is gather than by {}", stringify!($($i)*), stringify!($($i2)*));
        } else {
            println!("{} is less than or equal to {}", stringify!($($i)*), stringify!($($i2)*));
        }
    }
}

compare1_two!(2 3 4, 5 6 1);
```

我们定义了两个可变参列表，在里面统计列表的和进行对比，我们需要注意三个点

1. 在拓展中我们同时使用了两个变量， __但是这里必须保证两个可变参数量相等__
2. 我们将可变参传给stringify!系统宏, 他能将可变参转为字符串
3. 调用时由于是两个可变参列表，这里有些区别，变量表达式没有加分隔符，因为这里是两个变量，加了分隔符会区分不清

#### 元变量表达式

在上面的章节我们定义了很多宏，每个宏都有入参，这成为元变量表达式，有时候我们想获取表达式的一些属性，例如对于`重复项`来说，我们希望得到元素数量和重复的次数，根据官网介绍对于重复项有以下操作可以获取, 除了$$ 外，其余操作都只能用在重复项表达式上.

以下是可用的表达式，其中`ident`是绑定的元变量的名称，`depth`是一个整数字面值

```
${count(ident)}：在最内层重复中，元变量$ident总共重复的次数。这等效于${count(ident, 0)}。
${count(ident, depth)}：在深度为depth的重复中，元变量$ident重复的次数。
${index()}：最内层重复的当前重复索引。这等效于${index(0)}。
${index(depth)}：在深度为depth的重复中，当前的重复索引，从内向外计数。
${length()}：最内层重复将重复的次数。这等效于${length(0)}。
${length(depth)}：在深度为depth的重复中，将重复的次数，从内向外计数。
${ignore(ident)}：将$ident绑定到重复中，但展开为空。
$$：展开为单个$，可以用于转义$符号，使其不进行转录。
```

然而在通过代码实现
```
macro_rules! metavariable_expressions {
    ($($item: expr), *) => {
        println!("传入的重复项： {}", stringify!($($item)*));
        $(
            println!("Repetition Index: {}", ${index()});
            println!("Repetition Length: {}", ${length()});
            println!("xxx {}", $item);
        )*
    };
}
```

__编译报错  `meta-variable expressions are unstable` 既然官方都还没有将这些用法稳定放出，那我们就不学这一块了__

#### 定义更便捷的日志打印

在其他平台尤其c/c++系列，我们会定义很多日志级别和打印，今天我们探索怎么定义一个声明式宏更便捷的打印一些信息。

```
use std::time::{SystemTime, UNIX_EPOCH};
macro_rules! LOG {
    (DEBUG, $($EXP: expr), *) => {
        let mut buffer = String::new();
        $(
            buffer.push_str(&format!("{:?}", $EXP));
        )*
        let now = SystemTime::now();
        let since_epoch = now.duration_since(UNIX_EPOCH)
            .expect("Failed to get timestamp");
        let seconds = since_epoch.as_secs();
        let milliseconds = since_epoch.subsec_millis();
        let formatted_time = format!("{:02}-{:02} {:02}:{:02}:{:02}.{:03}",
            (seconds / 60 / 60 / 24 % 12) + 1, // Month
            (seconds / 60 / 60 / 24 % 31) + 1, // Day
            (seconds / 60 / 60 % 24),         // Hour
            (seconds / 60 % 60),              // Minute
            (seconds % 60),                   // Second
            milliseconds                      // Milliseconds
        );
        println!("{}: [DEBUG] {}", formatted_time, buffer);
    };
}
```

我们先来解释一下代码的含义

1. 入参首先匹配字面量DEBUG，然后匹配可变参列表
2. 创建可变字符串，拓展可变参列表，使用push_str追加字符串引用，这里使用了一个宏format! ，和print类似格式化字符串的
3. 获取时间戳字符串，这里用到了连个系统类, 剥离1970 年 1 月 1 日 00:00:00 UTC（协调世界时）的秒和毫秒
4. 默认方式打印几个得到的参数

我们来看一下打印效果

```
let parameter1 = "fbwebjdw";
let parameter2 = (10, "12", "ddd");
LOG!(DEBUG, "this debug log parameter1：", parameter1, ", parameter2：", parameter2);

10-27 07:18:32.762: [DEBUG] "this debug log parameter1：""fbwebjdw"", parameter2："(10, "12", "ddd")
```

我们看到打印出了想要的格式，唯一不对的是多了双引号，这个是{:?}打印带来的，另外时区也不对，这些后面的章节再讨论，目前我们的自定义日志格式宏已经实现了

#### 实现一个gruad-let语句

在枚举的章节中我们认识到了可选枚举`Option` , 对于可选枚举来说有两种方式解析 `if-let`或者`match`匹配, 我们再来回顾一下写法

```
let t = Some(64);
match t {
    Some(x) => println!("t is: {}", x),
    _ => println!("t is None"),
}
if let Some(x) = t {
    println!("t is: {}", x);
}
```

这里t中的64存储在常量数据区，不存在所有权转移，因此可以二次对t解析。我们回顾完Option来想一个问题，如果有n个可选变量，都有值的时候在做某件事，按照以上两种写法大概会是什么样子

```
if let Some(x) = n1 {
    if let Some(y) = n2 {
        ...
    }
}
```

代码会有无穷多的嵌套，在swift中有一个语句用来解决这个问题 gruad-let

```
gruad let x = option else {
    // 解析失败
    // do sth
    return;
}
// option解包成功，原始值已被绑定到x
// do sth
```

我们参考swift能不能自定义一个解析宏呢？我们先看看之前的章节，实现gruad-let的代码

```
let num = Some(50);
let raw_value;
if let Option::Some(n) = num {
    raw_value = n;
} else {
    return;
} 
println!("num is {:?}", raw_value);
```

可能有些人已经忘记了，我再来解释一下这段代码

* 初始化一个可选值

* 创建外部不可变变量raw_value，这里解析成功后会绑定值，解析失败会return，因此在使用到raw_value一定能保证有值。如果能保证使用时有值便可以延时初始化let变量

* 可选解析，解析成功赋值，失败返回

* 打印解析后的值

这里我们成功的将解析后的值传递到下文进行使用，当然我们学习了函数，也可以使用`函数体表达式`来做这个事情

```
let num = Some(50);
let num = {
    if let Some(x) = num {
        x
    } else {
        0
    }
};
println!("num: {}", num);
```

这里我们关注几个点

* 变量重影，或者重绑定，第一个num声明为 Option\<Integer>类型, 第二个则是Integer类型， 不懂重影的建议再回去看看以前的章节。
* 利用函数体表达式解析值，成功返回解析值，失败返回0

这里唯一的缺点是，返回的0不知道是解析成功还是失败。我们尝试用宏来定义一个类似swift的gruad-let语句

```
macro_rules! gruad_let_return {
    ($opt:expr) => {
        if let Some(x) = $opt {
            x
        } else {
            return;
        }
    };
}

// 可选值宏解析
let a = Some(40);
let a = gruad_let_return!(a);
println!("{}", a);
```

我们重影将原始值继续绑定到a，宏解析成功将原始值赋值给a 失败退出整个函数

#### 看几个系统定义的宏

```
macro_rules! matches {
    ($expression:expr, $pattern:pat $(if $guard:expr)? $(,)?) => {
        match $expression {
            $pattern $(if $guard)? => true,
            _ => false
        }
    };
}
```

* 首先匹配一个表达式
* 其次匹配一个逗号 （注意逗号后的空格是被忽略的）
* 接着匹配一种模式， 关于模式有哪些，参见官网match
* 接着跟一个if + 表达式 整体匹配0-1次
* 接着匹配0-1次逗号   咱也不知道为啥匹配这个逗号，目前看没啥用
* match匹配则个表达式
* 如果模式匹配 并且if $guard为真 则返回true
* 否则返回false
