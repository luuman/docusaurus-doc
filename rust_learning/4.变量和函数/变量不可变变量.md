### 变量/不可变变量

变量分为可变和不可变，其中可变的我们用 `let mut` 修饰，不可变的变量我们使用`let`修饰

```
let a = 10;
// a = 20; // 报错因为a不可变
let mut b: i32 = 10;
println!("a: {}, b: {}", a, b); // 此行不写会报错 maybe it is overwritten before being read?
b = 20;
println!("a: {}, b: {}", a, b);
```

概念我们在这里就不说了，我们能看到b在初始化为10后我们马上使用了b触发了read， 因为不读取的话编译时会报警告`maybe it is overwritten before being read?` 意思是初始化的值还未使用就被覆盖了，以此来提醒程序员初始化的10是无用的，请将两行合并为一行。可以看到rust编译器为开发设计了更为全面的警告。

__不可变变量的实际意义，从我个人角度出发，阅读c++/c代码时看到一个变量，想搞清楚他是干嘛的不仅要查看他参与的逻辑，还要查阅他的条件修改分支，如果声明为不可变，在意识里就能明确这个变量不会被修改，在阅读层面更清晰，不论swift还是rust都在编译层面帮助程序员确定变量的修饰符__

### 使用_忽略未使用的变量

在swift中，如果定义一个变量未使用，编译器会提示未使用此变量，请替换为_

```
let _ = 5
```

在rust中需要变量名以_前缀开头，以此来忽略编译器警告，经过尝试直接使用_也是 `_` 可以的

```
fn main() {
    let _x = 5;
    let _ = 10;
}
```

以上两个都不会触发编译器警告

### 单例

在oc中我们按照如下实现单例

```
static id _instance = nil;
static dispatch_once_t onceToken;
dispatch_once(&onceToken, ^{
    _instance = [[self alloc] init];
});
```

我们通过Dispatch框架提供的dispatch_once语句来保证线程安全和只赋值一次实例变量，在swift中我们
```
static let shared = Singleton()
```

swift中删除了dispatch_once原语，进而替代的是swift_once(这个查看源码或堆栈可得到)，这个方法包含于static变量的初始化，我们知道static声明的属性是属于Type的，而且只有一份，因此结合static能很好的实现线程安全并且保证只有一份

### Rust中的单例

接下来我们探讨在rust中实现一个线程安全的单例，我们知道rust提供了非常多的线程同步原语，组合非常复杂。

1. lazy_static

   ```
   // toml依赖
   [dependencies]
   lazy_static = "1.4"
   
   use lazy_static::lazy_static;
   use std::sync::Mutex;
   
   struct Singleton {
       // 单例的状态
       data: String,
   }
   
   lazy_static! {
       static ref INSTANCE: Mutex<Singleton> = Mutex::new(Singleton {
           data: String::from("Singleton instance"),
       });
   }
   
   fn main() {
       // 获取单例实例
       let instance = INSTANCE.lock().unwrap();
       println!("{}", instance.data);
   }
   ```

   lazy static是一个单独的crate，我们需要引入这个crate，它的作用是延迟加载静态变量，并且保证变量只加载一次。通过Mutex来保证多线程访问时的线程安全。__这种方式连续两次获取实例会死锁，记得加大括号限制锁的生命周期__

2. once_cell

   ```
   // // toml依赖
   [dependencies]
   once_cell = "1.8.0"
   
   use once_cell::sync::Lazy;
   
   struct Singleton {
       data: String,
   }
   
   static INSTANCE: Lazy<Singleton> = Lazy::new(|| Singleton {
       data: String::from("Singleton instance"),
   });
   
   fn main() {
       // 获取单例实例
       let instance = INSTANCE.clone();
       println!("{}", instance.data);
   }
   ```

   once_cell crate 是另一个常用的 Rust crate，可以实现懒加载的现成安全的全局静态变量。

3. Arc + Mutex

   ```
   use std::sync::{Arc, Mutex};
   
   struct Singleton {
       data: String,
   }
   
   impl Singleton {
       // 获取单例实例的方法
       fn get_instance() -> Arc<Mutex<Singleton>> {
           // 使用懒加载创建单例实例
           // 这里使用了 Arc 和 Mutex 来实现线程安全的单例
           // 只有第一次调用 get_instance 时会创建实例，之后都会返回已创建的实例
           static mut INSTANCE: Option<Arc<Mutex<Singleton>>> = None;
           unsafe {
               INSTANCE.get_or_insert_with(|| {
                   Arc::new(Mutex::new(Singleton {
                       data: String::from("Singleton instance"),
                   }))
               }).clone()
           }
       }
   }
   
   fn main() {
       // 获取单例实例
       let instance1 = Singleton::get_instance();
       let instance2 = Singleton::get_instance();
        // 修改单例数据
       {
           let mut instance = instance1.lock().unwrap();
           instance.data = String::from("Modified singleton instance");
       }
        // 输出单例数据
       {
           let instance = instance2.lock().unwrap();
           println!("{}", instance.data);
       }
   }
   ```

   我们来解释一下这个方法，首先我们看到其没有依赖额外的crate

   * 在 `Singleton` 结构体上实现了一个名为 `get_instance` 的方法。该方法返回一个 `Arc<Mutex<Singleton>>` 类型的实例，用于获取单例对象。

   * 定义了一个 `static mut INSTANCE` 变量，它是一个 `Option<Arc<Mutex<Singleton>>>` 类型，用于存储单例对象的实例， `Option` 则表示它可能为空
   * `unsafe` 关键字包裹的代码块是为了在 Rust 中使用内部可变性的 `get_or_insert_with` 方法。这个方法接受一个闭包作为参数，只有在 `INSTANCE` 为空时才会执行该闭包，并将闭包的返回值插入到 `INSTANCE` 中
   * 闭包内部首先创建了一个 `Arc<Mutex<Singleton>>` 类型的实例，使用 `Arc::new` 创建了一个引用计数智能指针，用于实现多线程间的共享。同时，使用 `Mutex::new` 将 `Singleton` 结构体包装在 `Mutex` 互斥锁中，以实现线程安全。
   * 最后，使用 `clone` 方法克隆 `Arc<Mutex<Singleton>>` 的实例，并返回该实例

   __这个是最应该掌握的__

4. Rc + RefCell

   ```
   use std::rc::Rc;
   use std::cell::RefCell;
   
   struct Singleton {
       data: String,
   }
   
   fn main() {
       // rc + refcell
       let instance5 = Rc::new(RefCell::new(Singleton {
           data: String::from("Singleton instance"),
       }));
       // 获取单例实例
       {
           let borrowed_instance = instance5.borrow();
           println!("{}", borrowed_instance.data);
       }
       {
           let mut borrowed_instance = instance5.borrow_mut();
           borrowed_instance.data = String::from("Modified5 singleton instance");
       }
       {
           let borrowed_instance = instance5.borrow();
           println!("{}", borrowed_instance.data);
       }
   }
   ```
   
   __这个目前没懂有屁用，是能获取多次一份数据，但是又不是全局的，加了static放外面就编译报错，后面在回来看吧__
### 常量

```
const a: i32 = 123;
const fn const_func() -> i32 {return 1;}
```

const修饰的为常量，他和不可变变量相比主要有以下区别：

* const 不允许与 mut 关键字一起使用，当然，这是显而易见的

* 对于 const 来说__必须声明类型__，而对于 let 来说类型是可以省略的
* const 声明常量只能使用一个常量表达式，而不能是函数调用结果或是在运行时才能确定的值，而 let 可以使用这些来进行声明赋值, 换句话说就是传给const的值必须确定
* const 可以在任意范围内（如函数体外）声明，而__let 只能在函数体中使用__
* const 常量不能够被覆盖，而 let 变量可以`let x = 5; let x = 10;`这样写不会报错
* const 常量没有模式推导功能，而 let 变量可以，所以必须写类型
* const 常量在编译期会被优化，进行常量传播，直接对引用的地方进行替换，所以编译后常量的使用一般会变成立即数指令，而 let 变量则会是直接寻址或间接寻址，性能消耗多一点（但是性能差距可以微小到不计）
* const 关键字可以作用在函数上，而 let 不行
* const 的命名规则是 `SCREAMING_SNAKE_CASE`，而 let 的命名规则是 `snake_case`

__函数可以用 const 关键字修饰，这样的函数可以在编译阶段被编译器执行，返回值也被视为编译期常量。const 函数是在编译阶段执行的，因此相比普通函数有很多限制，并非所有的表达式和语句都可以在其中使用__
