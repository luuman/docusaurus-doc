# 引用与借用

```
let a = 1;
let b = &a;
println!("b: {}, size_of b {}", b, std::mem::size_of_val(&b)); // 8字节指针
let c = *b + 1;
```

这个和c语言类似，&取地址赋值，占用8字节，*获取指向地址的真实值

```
let a: String = String::from("11");
let a1 = &a;
let _c = a; // 报错 cannot move out of `a` because it is borrowed
let count = a1.chars().count();
```

__引用类似c/c++的指针，可以使用*解引用，引用使用期间原值不能发生所有权转移(包括结构体内部成员)__

### 不可变引用

使用let修饰的引用类型是不可变引用。我们知道一般情况下原始值存储在堆栈，我们使用取地址符对其引用，会得到一个8字节指针指向，在rust中`let`修饰的引用是不可变引用，而且调用方法时可以无限进行引用叠加，如下

```
let s = String::from("11");
let s1 = &s;
let s2 = &s1;
let _count = s2.chars().count();
```

这和其他语言是不同的，其他语言中是做不到的，例如c++

```
class MyClass {
public:
    void myMethod() {
        std::cout << "Hello from myMethod!" << std::endl;
    }
};

int main() {
    MyClass obj;
    MyClass*  ptr  = &obj;
    MyClass** ptr1 = &ptr;
    ptr->myMethod(); // 通过指针调用方法
    ptr1->myMethod(); // 报错 Member reference base type 'MyClass *' is not a structure or union
    return 0;
}
```

那么rust是如何做到逐层解引用的呢, 我们看一下其MIR

```
fn main() -> () {
    let mut _0: ();
    let _1: std::string::String;
    let mut _5: std::str::Chars<'_>;
    let _6: &str;
    let mut _7: &std::string::String;
    scope 1 {
        debug s => _1;
        let _2: &std::string::String;
        scope 2 {
            debug s1 => _2;
            let _3: &&std::string::String;
            scope 3 {
                debug s2 => _3;
                let _4: usize;
                scope 4 {
                    debug _count => _4;
                }
            }
        }
    }

    bb0: {
        _1 = <String as From<&str>>::from(const "11") -> [return: bb1, unwind continue]; // 字符串赋值
    }

    bb1: {
        _2 = &_1; // 第一层引用 &String
        _3 = &_2; // 第二层引用 &&String
        _7 = deref_copy (*_3); // 编译器自动解引用为&String
        _6 = <String as Deref>::deref(_7) -> [return: bb2, unwind: bb6]; // deref将&String转换为&str
    }

    bb2: {
        _5 = core::str::<impl str>::chars(_6) -> [return: bb3, unwind: bb6];
    }

    bb3: {
        _4 = <Chars<'_> as Iterator>::count(move _5) -> [return: bb4, unwind: bb6];
    }

    bb4: {
        drop(_1) -> [return: bb5, unwind continue];
    }

    bb5: {
        return;
    }

    bb6 (cleanup): {
        drop(_1) -> [return: bb7, unwind terminate(cleanup)];
    }

    bb7 (cleanup): {
        resume;
    }
}
```

我们看懂不论你嵌套多少层，编译器都会添加deref_copy解引用，最后通过deref方法替换为没有搜有权的切片引用。__在Rust中这一点是通过Deref trait 和 Deref coercion， Deref trait 定义了解引用操作符 `*` 的行为，而 Deref coercion 是 Rust 编译器自动应用的规则，用于将引用转换为期望的类型。__

__不可变引用使用let修饰，可以存在多份，不论嵌套几层都由Deref trait在编译器负责解引用，解引用后只能按照let不可变使用__

### 可变引用

和不可变引用不同，我们已经知道了编译器的自动解引用机制，最后会变换成期望类型，在原始的期望类型中有一些操作是需要改变原始存储值和大小的。例如

`push_str`方法，在原始地址上直接修改内存的值。此时需要使用 `&mut` 进行可变引用

```
let mut ss = String::from("11");
let ss1 = &mut ss;
ss1.push_str(" 22");
println!("ss {}", ss1);
(*ss1) = String::from("你好");
println!("ss {}", ss);
```

* 原始类型需要支持可变操作 （修饰为let mut）
* 使用&mut获取其可变引用
* 可以利用s3使用可变方法，或者*s3使用

### 引用的使用规则

1. 可变引用只能同时存在一份

   ```
   let mut s = String::from("hello");
   let r1 = &mut s;
   let r2 = &mut s; // cannot borrow `s` as mutable more than once at a time
   println!("{}, {}", r1, r2);
   ```

   这个很容易理解，我们不希望上下文有两份同时可修改原始内存的指向，这样会产生歧义代码也不易于理解。我们可以简单理解为写写互斥(然而实际上s和r1都可以操作原始地址), 这个写写互斥是引用类型之间的

2. 不可变引用不能和可变引用同时存在

   ```
   let mut s = String::from("hello");
   let r1 = &s;
   let r2 = &s;
   let r3 = &mut s; // cannot borrow `s` as mutable because it is also borrowed as immutable
   println!("{}, {}, and {}", r1, r2, r3);
   ```

   这个很容易理解，我们可以简单理解为读写互斥
   
2. 所有权对象被引用时，不能再使用过程中转移其所有权

   ```
   let str = String::from("A");
   let r = &str;
   let str1 = str; // cannot move out of `str` because it is borrowed
   r.as_bytes();
   ```
   
   这个也容易理解，所有权被移走后原始对象就可能被释放(新老编译器不同)，会导致r变成野指针
   
2. 拥有所有权的对象，其被引用时，只能通过原始变量或者引用来操作原始值，我们不能通过解引用使用原始值

   ```
   let str = String::from("A");
   let r = &str;
   *r; // cannot move out of `*r` which is behind a shared reference
   ```
   
   我们通过解引用来访问其值，这是不被允许的，虽然人为认为*r和str是等价的，但是\*r对编译器来说是不定的，因为编译器并不清楚r指向哪个变量并不会对比两者，str对字符串值保留所有权，但是\*r没有所有权并不能直接通过它访问值

   ```
   let str = String::from("A");
   *(&str); // cannot move out of a shared reference
   ```
   
   这个case更加直观，不能对引用的8字节解引用访问其值
   
   ```
   let str = String::from("A");
   let r = &str;
   let bytes1 = (*r).as_bytes(); // 编译通过
   let bytes2 = (*r).into_bytes(); // 编译报错 cannot move out of `*r` which is behind a shared reference
   ```
   
   这里我们留个问题，大家可以自己去探索一下为什么一个编译通过一个编译报错？这里给大家提示一下 --- 具有所有权转移的值只能通过引用或者所有权变量操作，如果是在思考不明白，大家可以去看一下as_bytes和into_bytes的方法定义
