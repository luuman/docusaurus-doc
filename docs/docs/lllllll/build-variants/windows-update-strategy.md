# 升级策略说明

## 🧪 一、升级检查策略

### ✅ 触发方式

| 触发场景                   | 行为说明               |
| -------------------------- | ---------------------- |
| 冷启动（首次启动）         | 启动后自动触发升级检查 |
| 账号密码登录               | 登录成功后触发升级检查 |
| 用户手动点击“检查更新”按钮 | 立即触发升级检查       |

### ✅ 自动升级开启时：

- 正在下载更新时会**弹出下载进度窗口**。

### ❗ 未配置升级地址：

- 客户端仍应收到服务端下发的轮询时间；
- 客户端将根据此轮询间隔周期性检查更新。

## 🔁 二、轮询策略（自动更新后台机制）

| 状态             | 策略说明                                         |
| ---------------- | ------------------------------------------------ |
| 获取升级数据成功 | 启动轮询器，周期为服务端配置时间，默认 24 小时。 |
| 获取升级数据失败 | 每隔 60 秒重试，最多尝试 5 次，失败则终止尝试。  |

## 🪟 三、升级弹窗展示逻辑

### 🧾 升级配置文件（约 1KB）下载完成后：

- 即显示升级弹窗；
- 弹窗行为取决于升级类型（见下）。

## ⬆️ 四、升级类型说明

### 1. 强制升级（Mandatory）

- 升级窗口**居中显示**，**不可拖动或关闭**；
- 用户必须完成升级流程，才能继续使用客户端。

### 2. 普通升级（Normal）

| 设置                 | 行为                                                       |
| -------------------- | ---------------------------------------------------------- |
| 自动升级开启（默认） | 后台静默下载，完成后弹出安装提示窗口；头像旁出现升级提示。 |
| 自动升级关闭         | 弹出独立升级窗口，需手动点击“升级”按钮完成流程。           |

### 3. 建议升级（Recommended）

- 同“普通升级”逻辑；
- 但**增加“忽略本次升级”功能**，用户可跳过此次更新。

## 📝 建议优化点（可选）

1. **升级配置文件签名验证**（防篡改）；
2. **日志记录每次升级行为**（便于问题排查）；
3. **版本号对比逻辑提取为公共模块**，供 CLI/前端复用；
4. **支持多语言提示**（升级窗口内容国际化）；
5. **下载断点续传机制**。
